# Violin Prince Autopilot

A staged, cloud-first short-video production pipeline. It runs on GitHub-hosted runners; the creator's computer does not need to stay on.

## Current production format

- 24-second vertical video, 720 × 1280.
- Three original AI-generated still illustrations.
- Gentle, varied camera movement across each still; this is not full text-to-video animation.
- Four-sentence English narration generated by Kokoro-82M on the cloud runner.
- An original synthetic string-style instrumental bed when no approved recording is available. This is not a real violin performance.
- Sentence-timed, phone-readable subtitles.
- A final FFmpeg MP4 with audio/video validation.
- Publishing is forced off. The workflow only creates downloadable review artifacts.

## Why production is now staged

The default **Full** option runs Prepare → Visuals → Render in one launch. Each successful package is uploaded immediately before the next stage begins. If a later stage fails, its earlier package remains available and does not need to be rebuilt.

1. **Prepare** — fetch research, choose a sourced story, write the script, create narration and the original soundtrack. It uploads a prepared-package artifact.
2. **Visuals** — create only the three scene images and build storyboard-preview.png. It uploads a visual-package artifact.
3. **Render** — assemble the MP4 from the saved files. It makes no Cloudflare Workers AI calls.

The individual Prepare, Visuals and Render options are available for repairs or revisions. If the visuals are not right, run **Visuals** again using the same Prepare run ID. Add overall visual direction in visual_feedback (for example, a more painterly illustration style, warmer lighting, clearer focal subject, or more depth). This regenerates only the images. If final video assembly fails, run **Render** again using the same Visuals run ID. It does not regenerate story, narration, soundtrack or scene images.

If the story itself needs changing, make a new **Prepare** run. This is the only stage that repeats research and planning.

## Running the workflow

Open **GitHub → Actions → Violin Prince Autopilot → Run workflow** on branch main.

### Normal first attempt — one launch

- Keep stage set to **full** (the default).
- Leave source_run_id and visual_feedback empty.
- Start the workflow once.
- The run will preserve the prepared-package and visual-package artifacts as separate checkpoints, then create the MP4.
- Download storyboard-preview.png from visual-package to review the generated visual direction, and download the cloud-video-preview artifact for the final MP4.

### Recover a failed Prepare run without repeating research

When a Prepare run fails after collecting sources, the diagnostic artifact may still contain research.json.

- Keep stage set to **full**.
- Enter the numeric Run ID of that failed Prepare run in source_run_id.
- Leave visual_feedback empty or provide an overall image direction.
- Start the workflow once.

The workflow downloads the earlier diagnostic artifact and reuses its saved research.json. It does not call GDELT or Google News again. The planner then applies one automatic narration correction if the generated script misses the word-count, sentence-count or subtitle limits. The prepared-package and visual-package checkpoints are still saved before later stages continue.

### Repair only the stage that needs it

- **Story/script problem:** choose Prepare; this repeats research, planning, voice and soundtrack.
- **Image/style problem:** choose Visuals, enter the Run ID from the original Full or Prepare run in source_run_id, and describe the desired overall direction in visual_feedback. Research, script, narration and soundtrack are reused.
- **MP4/rendering problem:** choose Render and enter the Run ID from the original Full or Visuals run in source_run_id. It reuses the saved images, narration and soundtrack and makes no AI calls.

Artifacts are retained for 14 days. Keep the relevant successful run IDs until you have downloaded the final MP4.

## Services, limits and privacy

- **GitHub Actions** runs the stages in the cloud. No local PC processing is required.
- **Cloudflare Workers AI** is used only in Prepare and Visuals. The workflow stops on permission, quota or rate-limit errors; it has no paid fallback.
- **Kokoro-82M** creates the synthetic narration on a CPU runner. Model weights are Apache-2.0.
- **Pillow and FFmpeg** create the storyboard, camera movement, subtitles and MP4.
- The current staged R2-free workflow does not require Cloudflare R2, D1, or a Worker deployment.
- Publishing is disabled by the workflow (PUBLISH_ENABLED=false).
- The optional daily schedule remains disabled unless the repository variable AUTOPILOT_SCHEDULE_ENABLED is explicitly set to true. It is not needed for the staged manual workflow.
- Do not put API tokens or passwords in prompts, files, source code or chat. Keep tokens in GitHub repository Actions secrets.

## Creative and editorial limits

- Three generated still images with camera movement, not generated video clips.
- Synthetic narration and synthetic soundtrack; neither is a real violin recording.
- The image prompts use a consistent cinematic storybook-illustration direction with layered depth and a portrait composition.
- The planner should only use supplied research, avoid unsupported claims and choose a family-friendly topic. If a story cannot be sourced, it should stop rather than invent details.
- No lyrics, copied scripts, third-party creator videos, identifiable living people, logos or copyrighted characters are requested in generated artwork.

## Repository files

- engine/run.py — research, story planning, scene generation, staged package validation and rendering.
- engine/voiceover.py — synthetic narration and sentence timing.
- engine/synth_audio.py — original synthetic string-style soundtrack.
- engine/tests/ — offline regression, model-contract, storyboard and FFmpeg render tests.
- .github/workflows/violin-prince-autopilot.yml — staged GitHub Actions workflow.
- .github/workflows/autopilot-checks.yml — offline code and workflow validation.
